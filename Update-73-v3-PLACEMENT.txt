6. AUTOMATIC PROVIDER-MODEL HEALTH (new ask): BUILT. Approach, in full: docs/ai/provider-health.md. In short:
 - New scheduled workflow Provider health (05:30 UTC daily, and on demand), command `ai health --live`, settings in ai_health.yaml (the owner's switch auto_update, default ON).
 - It extends the FreeDiscoveryClient pattern: AnyAPI and OpenRouter (:free ids) and OVH (keyless) now publish live lists that are discovered; providers without a list have their pinned models probed.
 - ONE tiny probe per model ("Reply with the single word OK.") records answered, ms, tokens, and the error class (dead 404, credits 402, rate-limited 429, timeout); the daily cap or remaining comes from the usage ledger.
 - Selector: rules first. Every probe-passed model is scored per job with the seven weights the tool already uses (quality 0.35, headroom 0.20, reliability 0.15, speed 0.10, cost 0.08, capability 0.07, terms 0.05). Guards: free providers only (a paid model is never added); COST GUARD: left out of a job when one call of that job would be more than 10 percent of the provider's daily token allowance (or one request more than 10 percent of its requests); the 1 percent in your example would leave every token-limited provider out of the 8,000-token jobs, so the share is a setting; CAPABILITY GUARD: text for text, reasoning for reasoning.
 - Claude judges ONLY what the rules cannot decide (a model never seen before in a job's top 3, a tie at the top, a job's previous top pick just died): one small summarized call, at most once a day, answer recorded with its reasoning, its pick must be among candidates that already passed the guards, else ignored. If the rules decide everything: zero Claude calls.
 - Auto-update, safe: the generated lists go to data/_shared/ai_rankings.json (which the router already reads) and data/_shared/provider_health.json; the router uses the generated lists only while fresh (3 days) and falls back to the static lists and the last retest otherwise. Only probe-passed models are added; dead ones drop out automatically; never a paid model; never the LAST working model of a job (kept and flagged); at most 6 different routes dropped or added per run; one readable commit per run (e.g. "Provider health 2026-11-25: dropped dead ..."), pushed directly with no human gate; one git revert undoes it; owner switch auto_update (off = report only).
 - SCOPE: the run commits ONLY those two files, one path at a time. No code, no workflow, no other data file, no setting. (It does write the usage ledger locally during the run; that file is not committed.)
 - Discovered models are added in memory as approved TEXT models of free providers, only while the health file is fresh; nothing is written into ai_providers.yaml.
 - Not proven until the first live run: the discovery calls against the real endpoints, Claude's judge call, and that the commit lands. The first run is Actions > Provider health.
