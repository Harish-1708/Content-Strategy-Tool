# Transcription backends (stage 5), in the order they are tried

1. **Groq Whisper** (free tier, `GROQ_API_KEY`): first. A file that is not of a type Groq accepts (flac, mp3, mp4, mpeg, mpga, m4a, ogg, opus, wav, webm), such as the unnamed download of a TikTok video, or a big video, is first turned into a small mono MP3 (a mono WAV if the runner's ffmpeg has no MP3 encoder) with ffmpeg.
2. **Cloudflare Workers AI Whisper** (`@cf/openai/whisper-large-v3-turbo`; the free Cloudflare account the pool already uses: `CLOUDFLARE_ACCOUNT_ID`, `CLOUDFLARE_API_TOKEN`): second, up to 10 MB of audio.
3. **Faster-Whisper** (free, CPU, on the runner): the local backup, installed with a pinned compatible pair, `faster-whisper==1.1.1` and `av==13.1.0`.
4. **VibeVoice-ASR** (Microsoft, MIT licence, the CPU-only BitNet variant): last. **The workflow installs it itself, in the same run, so no repository variable is needed**: it installs cmake and build-essential, clones `microsoft/VibeASR.cpp`, builds it, downloads the model `microsoft/VibeVoice-ASR-BitNet` with `huggingface_hub.snapshot_download` (the `huggingface-cli` command no longer exists in current versions: using it was the exit-127 failure of probe-transcribe #4), and exports the command `asr_infer --vae-model ... --lm-model ... --audio {audio} -t 4 --greedy`. A repository variable `VIBEASR_COMMAND`, if you ever set one, wins over the installed command.

**An install failure is never hidden.** The install step used to be `continue-on-error`, which turned a failure into a green check. Now every stage of the install checks itself; a failure writes an ERROR annotation on the run, a line in the job summary and `VIBEASR_INSTALL_ERROR`, and the probe's VibeVoice line then says "the workflow's own install of it FAILED: <why>". The other three backends still run, because they do not depend on it.

**The probe transcribes real speech.** `probe-transcribe` makes a short spoken sentence with `espeak-ng` ("This is a test of the transcription chain. One, two, three.") and asks every backend to transcribe it: a backend passes only if the words it hears include some of the sentence, and its line shows what it heard (`TRANSCRIBED ... (heard: '...')`). Without that sample (espeak-ng could not be installed) the probe falls back to the old connectivity check on a second of silence, and says CONNECTED, not TRANSCRIBED.

What is still unproven until a run shows it: the format of what `asr_infer` prints (the probe will show whether the words come back), and the model download size on the runner.

Not wired: OpenRouter's audio endpoint (nothing here shows it carries a free Whisper route). The measured order is written by Actions > Stage tools > `probe-transcribe`; a backend that fails is left last, never dropped. When one backend stops working the next is used; the run fails only when every backend has failed, and then it says why for each.
